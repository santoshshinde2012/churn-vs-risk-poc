# Getting started

Everything runs locally on open-source Python in about a minute. No cloud account, no
credentials, no network access, no personal data.

## Prerequisites

- **CPython 3.10 – 3.13.** The upper bound is the pinned dependencies, not the code: those
  versions have wheels, and on 3.14 pip tries to build matplotlib from source and fails.
  `setup.sh` finds a supported interpreter on your `PATH` and prints which one it picked.
- **~600 MB of disk** (most of it MLflow's dependency tree) and about 1 GB of RAM.
- Nothing else. No Docker, no database, no GPU.

## Install

```bash
git clone https://github.com/santoshshinde2012/churn-vs-risk-poc.git
cd churn-vs-risk-poc
./setup.sh
```

`setup.sh` creates `.venv/` and installs the pinned dependencies. To use a specific
interpreter:

```bash
PYTHON=/path/to/python3.12 ./setup.sh
```

## Run

```bash
.venv/bin/python run_all.py
```

`make setup && make all` does the same thing. Expected output:

```
==============================================================================
SUMMARY
==============================================================================
  ok       1.8s  tests
  ok      14.2s  01_churn_batch_pipeline.py
  ok      11.0s  02_risk_realtime_pipeline.py
```

The complete console output of a real run is committed at
[`sample_run.txt`](sample_run.txt) — read that if you want the whole thing without running
anything.

### Running pieces

```bash
.venv/bin/python run_all.py 02 03    # just these scripts
.venv/bin/python run_all.py --keep   # don't clear outputs/ first
.venv/bin/python run_all.py --no-tests
make test                            # just the test suite
make clean                           # delete every generated artifact
```

Run them in order the first time — 03, 04 and 05 read artifacts that 01 and 02 write.

`run_all.py` clears `outputs/` first, because the MLflow registry and the inference log are
both append-only and a dirty directory makes a run non-reproducible. `--keep` is there for
when you want to watch the promotion guard refuse a worse candidate.

## Where the results land

```
outputs/
  metrics/     one JSON per pipeline — every number in the docs comes from these
  plots/       every figure
  tables/      scores, the call list, drift history, the live sample
  inference/   the request log, with model and policy version on every row
  models/      artifacts and cached state the later scripts reuse
  mlruns/      MLflow tracking and the @champion aliases
  dashboard.html   a self-contained summary of the whole run
```

`outputs/` is gitignored and fully regenerated by `run_all.py`. The figures the docs display
are committed copies under [`docs/images/`](https://github.com/santoshshinde2012/churn-vs-risk-poc/tree/main/docs/images).

Open `outputs/dashboard.html` in a browser for a single page containing every headline
number and figure from your run — it embeds its own assets, so it can be shared on its own.

## Troubleshooting

**`setup.sh` says no supported interpreter found.**
The pins need CPython 3.10–3.13. Install one (`brew install python@3.12`,
`apt install python3.12-venv`) or point at an existing one with `PYTHON=`.

**pip fails building matplotlib from source.**
You are on 3.14 or newer. Same fix as above.

**`03_live_scoring_demo.py` cannot bind port 8091.**
Something else is using it. Change `PORT` at the top of the script.

**`04` or `05` fails with `FileNotFoundError` under `outputs/models/`.**
They read artifacts that 01 and 02 write. Run `python run_all.py`, or run 01 and 02 first.

**`03` prints `registry unavailable`.**
It falls back to the joblib bundle and still works. It means `outputs/mlruns` was cleared
without re-running 02.

**MLflow says `@champion` was not promoted.**
That is the guard doing its job: the candidate did not beat an incumbent left over from a
previous run. `run_all.py` clears `outputs/` first and avoids this; `--keep` is how you
reproduce it deliberately.

**Numbers differ from the docs.**
Check `pip freeze` against `requirements.txt`. scikit-learn changes estimator internals
between minor versions, which moves calibrated probabilities. Run
`scripts/verify_claims.py` to see exactly which claims moved and by how much.

**The scripts are slow.**
Most of the time is model fitting. Drop `CHURN_ACCOUNTS` and `RISK_ACCOUNTS` in
[`churnrisk/config.py`](https://github.com/santoshshinde2012/churn-vs-risk-poc/blob/main/churnrisk/config.py); everything still runs, the numbers just get
noisier.

## Extending it

Start in [`churnrisk/config.py`](https://github.com/santoshshinde2012/churn-vs-risk-poc/blob/main/churnrisk/config.py) — every constant worth changing is
there, in one place.

| Want to try | Change |
| :--- | :--- |
| A different label window | `CHURN_LABEL_WINDOW`; section 1 of script 01 shows what it costs |
| Faster or slower chargebacks | `RISK_MATURATION_DAYS`, and the delay distribution in `risk_data.generate_stream` |
| Different costs, bands or fail modes | [`policies/*.yaml`](https://github.com/santoshshinde2012/churn-vs-risk-poc/blob/main/policies) — no code change, and script 03 replays both versions side by side |
| A new rule | [`churnrisk/rules.py`](https://github.com/santoshshinde2012/churn-vs-risk-poc/blob/main/churnrisk/rules.py): add a `_check` method and a block in the policy YAML |
| A bigger or smaller exploration slice | `EXPLORE` in `04_feedback_loops.py` |
| A different alarm | `WINDOW_DAYS`, `BASELINE_DAYS`, `Z_ALERT` in `05_monitoring_two_clocks.py` |
| Your own data | Replace the generators. Everything downstream depends only on the column contracts in `churn_data.FEATURES` and `risk_data.FEATURES` |

If you change something that moves a headline number, update
[`docs/claims.yaml`](claims.yaml) in the same commit — `verify_claims.py` will tell you
exactly which claims you moved.
